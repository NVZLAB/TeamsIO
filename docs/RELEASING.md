# Publishing updates

The application anonymously checks https://api.github.com/repos/NVZLAB/TeamsIO/releases/latest. A private repository, draft release, or Git tag without a published release cannot supply public updates. No GitHub token belongs in the desktop app.

## First public release

Commit the reviewed source and dependency lock files to main. When the repository is ready for public access, change its visibility in GitHub. Tag the reviewed commit with the project version, for example v1.0.0, and push the tag. The workflow tests, audits dependencies, scans publication files for secrets, builds the installer, and creates a draft release. Review the assets and publish that draft as a stable release. These repository changes are maintainer actions; building locally does not perform them.

Each release requires:

- Tag vX.Y.Z matching Version in TeamsIO.csproj.
- TeamsIO_Setup_X.Y.Z.exe from the same build.
- update.json generated by installer/New-UpdatePackage.ps1 after compiling the installer.
- Release notes in the GitHub release body.

For every later update, increment Version, update RELEASE_NOTES.md, and repeat the tag/release flow. Version comparisons are numeric; development suffixes and four-part versions are not supported. Mark the intended stable release as Latest in GitHub. Already-installed versions only offer releases with a higher version.

## Local validation

Use Windows and the SDK specified by global.json. Keep the SDK current because self-contained releases bundle their own .NET runtime. When intentionally changing dependencies or SDK runtime packs, run dotnet restore TeamsIO.sln --force and review both packages.lock.json files before committing them. CI uses locked restore and rejects known vulnerable dependencies or failed vulnerability queries.

```powershell
dotnet test TeamsIO.sln -c Release -p:RestoreLockedMode=true
dotnet publish TeamsIO.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:RestoreLockedMode=true
& "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" installer\TeamsIO_setup_script.iss
./installer/New-UpdatePackage.ps1
$env:TEAMSIO_RELEASE_DIRECTORY = "$PWD\installer\Output"
dotnet test TeamsIO.sln --no-restore --filter FullyQualifiedName~ReleaseIntegrationTests.PackagedInstaller
```

The last check feeds the real installer and manifest through the updater using simulated HTTP responses, verifies the downloaded bytes, and verifies the launch handoff without executing Setup.

After the public release exists, validate the real endpoint with:

```powershell
New-Item -ItemType Directory -Force artifacts | Out-Null
$env:TEAMSIO_LIVE_CHECK_OUTPUT = "$PWD\artifacts\live-update-check.json"
dotnet test TeamsIO.sln --no-restore --filter FullyQualifiedName~ReleaseIntegrationTests.LivePublicGitHubCheck
Get-Content $env:TEAMSIO_LIVE_CHECK_OUTPUT
```

Then use an older installed version on a test PC: Check for Updates > Download Update > Install. Verify the new version and retained connection/window settings. A same-version install should report up to date. This final production check requires a published release and is not replaced by mocked tests.

## Trust and signing

Downloads use HTTPS, repository/tag-bound asset URLs, restricted GitHub CDN redirects, size/time limits, and SHA-256 verification. The installer is verified again while locked immediately before launch. Windows Internet-zone metadata is retained. Checksums establish consistency with the release manifest; they do not independently authenticate a publisher if the GitHub release account is compromised.

Protect maintainer accounts with MFA and the main branch/tags with repository rules. Use an Authenticode signing certificate or signing service for production distribution. This project does not contain a signing key; the locally produced installer is unsigned unless a maintainer signs it. Sign the installer before generating update.json, since signing changes its checksum. Never replace assets for an already published version; create a new version.

GitHub API reference: https://docs.github.com/en/rest/releases/releases
